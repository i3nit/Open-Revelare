# 手绘细条带修复

这一路径针对横向、斜向或缓慢弯曲的细干涉条带。它不要求圆心或同心环，也不要求图中出现完整圆环。原有频谱与 AI 按钮保留。

## 使用

1. 在「去牛顿环（实验）」中，用「涂抹区域」覆盖实际受影响的条带；可以分别画上下两条，不必把中间画面选进去。用排除笔保护文字、真实重复纹理等位置。
2. 设置「条带方向」：按照**当前显示画面**，横向填 0°，竖向填 90°，斜向填对应角度。裁剪、拉直、90° 旋转和翻转会自动换算到传感器坐标，不需要自己反算角度。
3. 点击「细条带修复（手绘）」。它只应用手绘范围，不会把整幅分析候选自动变成修复区。
4. 关闭蓝色蒙版，在 100% 或局部放大预览中比较。修复强度、亮度纹比例和排除笔仍可调整，分析可取消，结果可撤销。

此路径先从原文件单独解码当前画面所在的区域，再将**该区域**缩到最长边不超过 1024；不从整幅扫描的低分辨率预览截取小画面。这样可以避免细条带在识别前已被整卷/整张预览的平均采样抹掉。一次区域解码会比普通预览占用更多内存，结果只保存有限尺寸的校正场。

## 方法与边界

分析沿用 log 线性源 RGB 中的局部频谱分解，新增带方向约束的频率选择，并允许更高频的条带。局部窗口允许条带缓慢弯曲、间隔变化；不是只拟合一条覆盖整图的直线。强烈转向、分叉、多个互相交叉的方向需分次选区并选择合适方向；重新分析会替换当前校正层，可撤销。

手绘范围提供的是位置先验，条带方向提供方向先验。方向滤波仍可能误伤方向、间距相近的真实图案，不能保证自动区分窗框、百叶窗、棋盘或印刷细纹。实际画面的横向结构应检查并按需排除。灰度条纹需要提高「亮度纹修复」比例，但也会更明显影响真实明暗细节。

针对性研究参考 [General Stripe Remover 官方实现](https://github.com/NiklasRottmayer/General-Stripe-Removal) 和 [VSNR 作者页面](https://www.math.univ-toulouse.fr/~weiss/Codes/VSNR/VNSR_VariationalStationaryNoiseRemover.html)。这些方法说明了条纹方向先验的用途；本实现没有复制它们的代码，也未复现其变分优化或使用其论文结果作为本功能效果。

## 校正场与兼容性

校正场附着到源图中的一个矩形，矩形外的校正为零；笔划仍存源图坐标。预览、局部放大和导出采样同一场，改变裁剪或翻转不会移动修复位置。改变画面范围之后若要修复原分析矩形外的新区域，需要重新分析。

局部场采用压缩载荷 v2，包含源矩形；此类工程保存为 `.ncproj` v6，旧程序会拒绝打开，避免静默丢掉修复。原有全源场仍写载荷 v1、工程 v5；未使用牛顿环的工程仍按原规则写 v2/v3/v4。读取时限制尺寸、载荷和矩形边界，保存重开不重新估计、不引入新的量化。

整数平均采样会丢掉末尾不足一个采样单元的行列，区域场记录的是实际保留下来的范围，不能将它重新拉伸到原矩形，否则细条带的相位会错位，产生新的残纹。

## 真实样片验证（2026-11-02）

依据用户标注的 DSC01937 上下两条带，在 RAW 副本上配置近似手绘范围。测试没有把截图上的黑色轮廓作为图像内容，也未用标注图训练 AI。比较使用较高分辨率的 RAW 渲染；默认强度 0.8、亮度纹比例 0.25。

此组对比未能证明有效去环；后续工作先转为 [独立识别验证](newton-detection-validation.md)。本地输出在 `scratch/newton-bands-verification/`：`DSC01937-comparison.jpg` 是原结果 / 修复 / 手绘范围三联图；`upper-detail.png` 和 `lower-detail.png` 为原结果 / 修复的局部对比。不能将此前局部视觉差异作为有效修复的证据；该方法仍可能保留真实条带或改变正常结构，尚未证明识别或去除可靠。

尚无无环配对参考图，不报告真实样片 PSNR、SSIM 或去环准确率。候选置信度覆盖不是实际牛顿环占比。复杂曲线仍可能需要更精确的手绘范围、分次分析和排除真实结构。

## 复现与回归

```sh
dotnet test src/OpenRevelare.Tests -c Release --filter 'FullyQualifiedName~Newton'
dotnet run --project benchmarks/OpenRevelare.NewtonVerification -c Release -- \
  <输出目录> <工程.ncproj或-> <RAW文件...> --bands=<配置.json>
```

配置使用源图归一化坐标，`direction_degrees` 以源图像素轴为准；GUI 会代为换算，命令行则需自行提供。示例：

```json
{
  "source_rect": [0.1, 0.1, 0.8, 0.8],
  "direction_degrees": 0,
  "strokes": [
    { "X": 0.3, "Y": 0.25, "Radius": 0.1, "Erase": false },
    { "X": 0.4, "Y": 0.25, "Radius": 0.1, "Erase": false }
  ]
}
```

回归覆盖正负透射极性、细水平/垂直/斜向弯曲条带、区域场相位与采样范围、局部/全图一致性、工程 v5/v6 选择、保存重开，以及裁剪旋转翻转后的真实手绘流程。
